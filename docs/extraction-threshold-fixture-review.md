# 청크 임계 정책용 합성 자료 v2

상태: 에이전트 작성·자동 대조 완료, **사람 검토는 pending**이다. 기존 v1의 사람 승인 문구를 이 자료에 적용하지 않는다. 자료 버전 2, 추출 인용 계약 2, 실험 판정 계약 2는 서로 다른 식별자다. 이 자료를 추가한 것은 모델 호출 승인이나 성능 입증이 아니다.

`verinote/benchmark_data/v2/manifest.json`이 각 JSON의 canonical SHA-256과 원문 SHA-256을 연결한다. `python scripts/build_threshold_fixtures.py`로 같은 자료를 다시 생성할 수 있다. 이 생성기는 모델을 호출하지 않으며 원문과 명시적 주석을 함께 작성한다. 생성 결과와 oracle의 일치만으로 정답의 의미가 검증됐다고 간주하지 않는다. 아래 의미 표, 독립적으로 적은 기대 triple, 잘못된 응답 대조군을 함께 확인한다.

| 자료 | production 청크 수 | 원문 문자 수 | 현재 직접 호출 정답 전체 |
|---|---:|---:|---|
| short | 1 | manifest에 연결된 source 참조 | S0 → S1 |
| three | 3 | 24,000 | S0 → S1, S1 → S2, S2 → S3 |
| four | 4 | 32,000 | S0 → S1, S1 → S2, S2 → S3, S3 → S4 |
| eight | 8 | 64,000 | S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7 → S8의 인접 호출 8개만 |

모든 정답의 predicate는 `calls`다. 승인 개체는 short/three/four/eight 각각 S0…S2/S4/S5/S9이며, 별칭은 없다. 관계는 calls·archives·mirrors 세 개다. 각 구간 n은 a=S(n−1), b=Sn, c=S(n+1)를 사용한다.

| 각 구간의 내용 | 기대 결과 |
|---|---|
| `현재 실제 구성: a는 b를 직접 호출한다.` | calls(a,b) 하나. 실제 구성이라는 문맥 전체를 인용해야 한다. |
| 동일한 호출 문구 앞에 `가정 예시(실제 아님)` | 별도 사실이 아니다. 공통 내부 문구만 인용하면 위치가 두 곳이므로 실패한다. |
| b가 a를 직접 호출하지 않는다는 부정 | calls(b,a)는 금지. 부정 문장에 근거한 claim을 요구한다. |
| 장애 때만 a가 c를 호출한다는 조건 | 무조건 calls(a,c)는 금지. 조건 근거 claim과 qualifier_not_representable gap을 요구한다. |
| 2020년에 a가 b를 보관했고 2025년부터 중단 | 현재 archives(a,b)는 금지. 과거·종료 문장 전체를 근거로 claim과 qualifier gap을 요구한다. |
| a가 승인되지 않은 OutsideN을 호출 | 새 개체를 사실로 만들지 않는다. 근거 claim과 missing_entity gap을 요구한다. |
| a가 b를 소유하지만 소유 관계가 사전에 없음 | 새 predicate를 만들지 않는다. 근거 claim과 missing_relation gap을 요구한다. |
| 직접 복제 근거가 없다고 명시 | mirrors coverage는 no_evidence. 사실을 억지로 생성하지 않는다. |

각 구간 coverage는 calls=extracted, archives=not_representable, mirrors=no_evidence다. calls는 조건·미등록 대상 claim을 참조하고 archives는 과거 claim을 참조한다. gap은 같은 code의 여러 claim을 한 항목으로 묶거나 나눌 수 있지만, 기대 근거를 빠뜨리거나 무관한 claim으로 대신할 수 없다.

3·4·8청크 자료는 각 8,000자 구간에 위 의미를 반복하되 개체·구간 식별자를 다르게 한다. 남는 공간은 구간별 번호가 붙은 중립 점검 기록으로 채운다. 실제 구성 정답은 각 청크 끝에 두며 근거의 end offset은 `8,000 × n − 1`이다. 문장 끝 다음 개행에서 청크가 끝나므로 경계에 걸친 불완전 인용을 정답으로 인정하지 않는다. short는 같은 의미 요소를 가진 짧은 준비 문서이고 긴 중립 기록은 없다.

## 평가 범위와 대조군

평가기는 현재 직접 호출의 정확한 정답 집합, 부정·조건·과거를 평탄화한 잘못된 사실, 근거 위치·유일성, production coverage 형식, 기대 coverage 상태와 claim 근거, gap code·근거의 완전성을 검사한다. 청크가 빠지면 완료로 인정하지 않는다. 참조 claim의 번호나 응답 내 순서 자체를 정답으로 고정하지 않는다.

이것은 **유한한 주석·근거 계약**이다. 자유롭게 작성된 모든 claim 설명문의 자연어 논리적 함의를 일반적으로 판정하는 도구가 아니다. claim 설명의 임의 의역·환각을 완전히 검출한다거나 자동 통과가 일반적 의미 품질 100%를 증명한다고 주장하지 않는다. 실측 보고는 이 한계를 명시해야 한다.

테스트는 정답 누락, 부정의 반전, 조건의 무조건화, 과거 보관의 현재 사실화, 가정/실제의 공통 인용, 과거 근거를 현재 근거로 교체, gap 누락·잘못된 code·무관한 claim 참조, not_representable을 no_evidence로 바꾸기, 청크 누락, 손상된 주석·버전 혼합을 각각 거부하는지 확인한다. v1의 보존된 기각 evaluation과 진단 JSON도 정확히 같아야 한다.

새 실행 도구는 실제 호출 전에 이 자료·gold·prompt·plan·코드의 해시를 묶어 보존해야 한다. 벤치마크 실행용 사전 승인은 합성 실행을 위한 것임을 기록하고 사람의 gold 검토로 표현하지 않는다. 구체 호출·시간·관측 토큰 예산 승인 전에는 실제 모델을 호출하지 않는다.
