# 질문 입력의 근거 공유와 전체 예산

질문 도구의 결과를 원본 그대로 매 회차 반복하면, 개별 결과 또는 누적 입력이 앱 또는 제공자 제한을 넘을 수 있다. 새 질문은 모델용 표현을 별도로 구성하고 최종 요청 전체를 전송 전에 검사한다.

## 원본과 모델 입력

저장된 `trace`, `evidence`, 의미 후보 및 UI의 출처·승인 상태는 수정하지 않는다. 새 `question_context` 표현 버전 2는 반복되는 JSON 하위 구조·긴 문자열을 `context_tables`에 공유하고 `{"$r":"key"}`로 참조한다. 반복 필드명은 `context_shapes`의 순서 있는 키 배열로 공유하며 `{"$o":["shape_id",[값들]]}`을 키·값 순서대로 복원한다. 중첩 참조를 지원하고, 실제 직렬화 비용에 이득이 있는 표현을 선택한다. 짧은 내부 참조는 모델 입력 안의 표현용이며 실제 `entity:`/`relation:` 참조나 인용 E-ID가 아니다.

내부 content hash의 충돌을 검사하고, 전체 복원 state의 SHA256에 snapshot과 모든 내용을 결합한다. ID가 같아도 revision·내용이 다르면 섞지 않는다. 없는 참조·순환·잘못된 객체 shape·중복 키·arity 불일치·변조를 거부한다. 복원 전에 논리적 확장량을 점진적으로 계산해 8 MiB/200,000노드/깊이 96을 제한하며, 공유된 값도 매 등장마다 원래 키·값 크기로 계산한다. 이 복원 자원 제한은 모델 입력 한도를 늘리는 것이 아니다. 기존 v1 입력을 읽는 전용 resolver와 고정 합성 fixture도 유지한다.

E-ID별 snapshot·query·status·rows·scoped references·증명에 쓰인 사실 ID는 유지한다. 정확한 사실·인용·출처·revision, 의미별 타입·승인 구분, 모호성·옛 계약 경고도 보존한다. 위키·원문 text와 offset/partial/claim_indices/next_offset, 검색 결과의 범위·잘림·이어 읽기 상태는 유지한다. 투영을 다시 해석해 원래 state와 정확히 같은지 검사한 후에만 요청을 구성한다. 이는 요약이나 근거 삭제가 아니다.

모델 지침은 공유 테이블 해석법과 사전 안내가 관계 증거가 아니라는 점을 명시한다. 실제 모델의 표 참조 이해나 답변의 자연어 의미 정확성을 보장하지는 않는다. 보존한 과거 질문·프롬프트·원본은 재작성하지 않는다.

## 전달과 인용

실제로 요청에 완전히 포함된 E/K-ID만 전달 후보가 된다. 모델 호출이 성공적으로 반환된 후에 전달 상태를 갱신한다. 호출 전 크기 검사 실패나 제공자 호출 실패는 새 근거를 전달된 것으로 처리하지 않는다.

최종 답변에는 전달된 그래프 조회가 필요하며, 인용도 모델이 전달받은 근거로 제한한다. K-ID는 검색 안내이며 인용 불가다. 같은 도구 batch에서 만든 근거·검색 결과를 이미 받은 것으로 처리하지 않으며, 원문 fallback의 이전 회차·완전한 검색·위키 읽기 요건을 유지한다.

## 전체 UTF-8 바이트 검사

지침·프로토콜·질문·catalog·공유 표·trace·모든 근거·회차 및 답변 전용 안내까지 포함한 **완성된 prompt의 UTF-8 바이트 수**를 검사한다.

- 앱 한도는 기존 60,000바이트다.
- Ollama는 실제 등록된 Job의 고정 options에서 `num_ctx - num_predict - 1024`를 계산한다. 기본값은 `32768 - 4096 - 1024 = 27648`바이트다. 질문 계층과 최종 transport 검사에서 같은 함수를 사용한다.
- 적용 한도는 앱 한도와 알려진 transport 한도의 최솟값이다. transport 한도를 알 수 없으면 앱 한도만 적용한다. 다른 제공자의 실제 모델 토큰 한도를 임의 추정하지 않는다.
- 정확히 한도인 입력은 허용하고 1바이트라도 초과하면 모델 호출 전에 중단한다. Ollama의 바이트 검사는 기존 보수적 admission이며 tokenizer 결과나 모든 모델의 context 적합성을 보장하지 않는다.

손실 없는 중복 제거 후에도 너무 큰 입력은 모든 기록을 분할 분석하고 종합한다. 단일 기록이 입력 예산을 넘으면 JSON 경로별 완전한 하위 값으로 분리하고, 그 자체가 큰 문자열이면 정확한 문자 offset과 total_chars로 나눈다. 모든 필드와 값을 보존하며 원본 ID·해시·조각 순번/개수를 붙인다. 원본 재구성 해시를 검증하고 조각별 처리 응답을 빠짐없이 확인한다. 필수 질문·지시·최소 조각조차 들어가지 않으면 전송 전 실패한다. 출력 상한·context 옵션을 올리거나 자동 재시도하지 않는다.

개별 도구 결과 30,000바이트 거부는 제거한다. 모델 출력의 30,000바이트 검증, 논리 최대 6회·도구 최대 10회와 마지막 답변 전용 규칙은 유지한다. 분할 시 회차당 기록·조각은 최대 2,048개이며 전체 물리 호출 상한은 24,576회다. 실제 계획은 묶음 수로 계산하여 전송 전에 저장한다. 전체 확장 상태의 8 MiB/200,000노드/깊이 96 자원 제한은 그대로 적용한다.

조각은 모델 입력의 `records`에 별도 fragment 종류로 전달한다. 부분 그래프를 완전한 E로 가장하지 않으며, 빠진 필드·관계·문맥은 미확인으로 다룬다. 인용 가능한 원본 E의 조각만 자신의 조각 ID를 인용할 수 있고, 서버가 이를 원본 E로 연결한다. 검색·카탈로그 조각은 인용이나 원문 fallback 권한을 얻지 못한다. 종합 답변은 기존처럼 A 분석 ID를 인용하는 inference만 허용한다. 원본 evidence와 trace, UI의 원본 표시 계약은 유지한다.

`context_processing`은 원본 해시, 조각 내용과 범위, 처리 manifest를 저장한다. 최종 A 인용 검증은 전체 조각 coverage·재구성 해시·현재 원본 근거의 해시를 확인한다. 모든 내용 전달과 처리 응답을 검증할 뿐 모델의 의미 이해·정확한 종합까지 보장하지 않는다. 큰 결과의 분할은 실제 모델 호출 수·시간·비용을 늘릴 수 있다.

## 진단과 검증

새 질문 JSON의 `context_budget` 배열에는 회차, 표현 버전, 실제 prompt bytes, 앱 한도, 알려진 transport 한도(모르면 null), 적용 한도, `within_limit`/`exceeded`를 저장한다. 진단 기록 자체는 다음 프롬프트에 누적하지 않는다. `within_limit`는 입력 admission 결과이며 모델 성공이나 실제 토큰 사용량을 뜻하지 않는다. 생성된 프롬프트는 기존 호출 로그에 보존되고, 전송하지 않은 초과 요청은 추가 호출 로그 대신 질문의 예산 기록으로 확인할 수 있다.

별도의 합성 동음이의어·반복 그래프와 모의 API로 기존 60KB 초과 사례, Ollama의 27,648바이트 경계, 첫 요청/후속 요청 초과, 다중 바이트 UTF-8, 원본 불변·완전 복원·미전달 인용/원문 접근 거부를 검증한다. 실제 사용자 문서를 테스트 입력으로 쓰거나 실제 모델을 호출하지 않는다. 작은 프롬프트와 성공적인 모의 두 번째 요청은 용량·제어 흐름 검증이며 실제 모델 품질 향상의 측정은 아니다.


## 풍부한 의미 catalog 회귀

처음의 반복 그래프 fixture는 의미 catalog가 작은 경우여서 실제 Store·사전·위키·승인 사실이 함께 있는 입력을 충분히 대표하지 못했다. 추가 합성 재현에서는 문서 2개도 두 번째 요청이 약 30KB, 4개는 약 45KB가 되어 v1 공유만으로는 Ollama 한도를 넘었다. 이 공백을 추가 회귀로 고정하고 v2의 하위 구조·문자열·필드명 공유를 적용했다.

새 회귀는 다른 합성 동음이의어로 문서 2개/4개를 실제 임시 Store에 구성한다. 실제 snapshot·의미 catalog·Wirelog 결과를 사용해 그래프 3개 및 그래프 2개+검색의 네 조합을 고정 Ollama Job과 모의 API로 실행한다. 네 조합 모두 전체 두 번째 prompt가 27,648바이트 이내여야 하며 모든 근거·catalog·증명·검색 완전성을 정확히 복원한다. 테스트 출력에 첫/두 번째 bytes, raw state/catalog 크기를 기록한다. 네 가지 사례의 통과가 모든 질문의 무제한 용량이나 실제 모델의 표현 이해를 보증하지는 않는다.
