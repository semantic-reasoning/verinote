# 출처별 개체 식별과 질문의 의미 후보

새 그래프는 같은 이름을 같은 개체로 자동 합치지 않는다. 개체·관계 참조는 문서 ID, 원문 버전, 추출 당시 사전 ID/revision/payload 해시, 사전 내 ID로 결정한다. 타입이 같아도 문서나 사전 출처가 다르면 별도 후보다. 이 분리는 두 개체가 실제로 다르다는 판정이 아니라 **동일성을 승인하지 않았다는 보수적 경계**다. 문서 간 동일성 승인·병합은 이번 기능에 포함하지 않는다.

예를 들어 합성 어휘 `차`가 서로 다른 사전에서 `음료`와 `이동수단`으로 선언된 경우, 질문이 어느 의미인지 지정하지 않으면 두 후보를 함께 표시한다. 질문에 없는 타입을 먼저 선택하지 않는다. 사용자 회귀 테스트도 이런 별도 합성 어휘로 수행한다.

## 승인과 재현

새 스냅샷은 `graph_identity_version=1`, 정규화된 `ontology_pins`, 사실별 pin 참조 `fact_ontologies`를 함께 고정한다. 승인 사실은 해당 실행의 고정 사전으로 해석한다. 현재 사전이 개정되거나 승인이 철회돼도 이미 독립적으로 승인된 사실을 다른 뜻으로 바꾸거나 조용히 삭제하지 않는다. 현재 승인 사전 안내와 추출 당시 사전은 표시를 구분한다.

고정 사전이 없거나 해시·구조가 잘못된 옛 사실은 문서·원문 버전 내부의 미해결 의미로만 연결한다. 다른 문서의 동명 노드에는 연결하지 않는다. 의미 식별 정보 자체가 관계 사실의 승인을 뜻하지 않는다. 위키와 관계 승인도 별개다. 검토 대기·보류·반려 사실은 승인 그래프와 의미 후보의 연결 사실에 포함하지 않는다.

DB 테이블 migration이나 기존 기록 재작성은 없다. 식별 계약 필드가 없는 과거 스냅샷은 기존 문자열 계산과 결과를 유지한다. 화면은 그 방식이 동명 의미를 구분하지 못한다는 한계를 표시한다. 새 snapshot/질문을 만들어야 새 식별 계약을 사용한다. 과거 결과를 현재 의미로 보강하지 않는다.

## 그래프 조회

`subject`, `predicate`, `target`은 기존 문자열 필드다. 사전 ID·이름·별칭 또는 결과에서 받은 `entity:<sha256>` / `relation:<sha256>` 참조를 사용할 수 있다. 표기는 정확히 일치해야 한다. 개체는 ID와 이름 어느 쪽으로도 선택되므로, 둘이 띄어쓰기만 다른 개체는 두 표기 모두로 선택된다([사전 조정](dictionary-reconciliation.md)의 기준에 맞는 개체는 사전 검토 화면에 표시된다). 명시적 참조는 해당 스냅샷에서 검증하며, 없는 참조나 개체/관계 종류가 틀린 참조는 거부한다. 두 접두사는 참조 선택용으로 예약된다. 이 접두사로 시작하는 값은 참조로만 해석하므로, 이렇게 시작하는 사전 ID·이름·별칭으로는 그 개체를 찾을 수 없고 다른 표기나 참조로 찾는다. 사전 내용 수정은 이 접두사로 시작하는 새 개체 ID·이름·별칭을 거부한다.

- `direct`와 `upstream`은 같은 이름의 여러 의미가 일치하면 각 의미의 결과를 분리해 반환한다. `upstream`은 선택한 관계의 도달 경로이며 관계의 의미 자체가 전이적이라는 보장은 아니다.
- `downstream`과 `path`에서 기준 개체·관계·도착 개체가 모호하면 `status=ambiguous`, 후보와 안내를 반환한다. 첫 번째 후보로 계산하지 않는다.
- 하나의 개체 참조를 선택하면 문자열 관계 ID는 그 개체의 사전 범위로 좁힌다. 관계 참조를 직접 지정할 수도 있다. `direct`는 `target`을 지원하지 않는다.
- 표시용 `rows`와 사실 payload는 유지한다. 실제 계산·증명은 참조로 수행하며, `row_refs`, 증명의 `row_refs`, `fact_refs`, `entities`, `relations`에 출처별 연결을 제공한다. 동일한 표시 삼중항이 여러 출처에서 나와도 증명과 사실 ID는 합치지 않는다.

화면의 **이 의미를 기준 개체/도착 개체/관계로 선택**은 고급 조회 양식에 참조와 같은 스냅샷을 채운다. 조회 방식·관계를 확인하고 조회를 실행한다. 이 동작은 모델을 호출하거나 기본 에이전트 설정을 바꾸지 않는다.

## 자연어 질문

서버는 고정 스냅샷에서 질문의 이름·별칭과 일치하는 의미 후보를 구성해 질문 결과에 저장한다. 한 글자 이름과 한국어 조사, Unicode 정규화를 처리하며 무관한 복합어 내부의 부분 일치는 피한다. 이는 어휘 탐색이지 질문 의도를 완전히 해석하는 알고리즘이 아니다. 입력에 의미를 좁히는 표현이 있어도 후보 안내가 그 의미를 확정한 것으로 표시하지 않는다.

각 후보는 타입·문서·원문 버전·사전 revision·원문 인용과 연결된 승인 사실을 보여준다. 사전 안내는 인용 가능한 그래프 증거가 아니다. 연결 사실은 승인된 직접 삼중항을 보여주는 것이며, 질문에 대한 추론 답변을 자동 생성한 것이 아니다. 모델은 실제 관계 ID/참조로 Wirelog를 조회하고 각 의미의 답변 근거를 구분하도록 안내받는다. 카탈로그의 한국어 동사를 관계 ID로 임의 치환하지 않는다.

모델이 모호성을 자연어 답변에서 누락해도 **가능한 의미** 패널은 서버 자료로 별도 표시된다. 승인 관계가 없으면 그 상태를 보이며 승인 위키에 근거한 설명과 구분한다. 모델 출력의 자연어 의미 정확성을 보증하거나 자동으로 사실을 승인하지 않는다.

안내는 최대 20개 후보와 10,000 UTF-8 바이트로 제한한다. 사전 인용은 최대 200자, 후보별 연결 사실은 최대 3개·인용은 최대 160자, 관계 안내는 최대 20개·설명은 최대 200자로 표시한다. 일부 생략·인용 일부 여부를 명시한다. 생략됐다고 한 의미로 확정하지 않으며 문서·참조로 범위를 좁혀야 한다. 기존 모델 문맥·도구 결과 한도도 유지하므로 큰 조회는 더 좁혀야 할 수 있다.
